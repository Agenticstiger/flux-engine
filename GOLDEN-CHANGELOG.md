# Golden changelog: `tests/golden/telco/`, `tests/golden/telco-public/` and `tests/golden/towers-public/`

Every deliberate move of a pinned artifact under `tests/golden/telco/`
(`plan.json`, `run-digest.json`, `seam-attestation.json`,
`fidelity-record.json`, `component-digests.json`) or
`tests/golden/telco-public/` (`run-digest.json`, `seam-attestation.json`,
`row-count.json`) gets one row here, keyed by that set's own
`run-digest.json`'s `runDigest` (the KERNEL-SPEC §11 digest taken over
that document with its self-referential fields masked; see
`tests/golden/test_telco_golden.py::_run_digest_value` and
`tests/golden/test_telco_public_golden.py::_run_digest_value`). A pinned
file that changed with no matching row here is a regression, not a
golden update: `test_a_golden_change_requires_a_changelog_row` in each
module enforces it, mirroring the same rule `fluxsim verify --update-golden`
already enforces for the runtime `<state_dir>/golden/GOLDEN-CHANGELOG.md`
(`flux_engine.core.trace.check_golden_update`).

Regenerate both sets with `python tests/golden/telco/_generate_golden.py`
(runs the full 25k-subject `tests/fixtures/telco-fidelity` bundle through
apply + ship, then the public `examples/telco-payment-recovery` bundle
from the sibling FLUX repo through apply alone), read the new
`runDigest`s back out of the regenerated `run-digest.json` files, and add
a row here per set in the same commit. Regenerate the towers set with
`python tests/golden/towers-public/_generate_golden.py` (the public
`examples/towers-tenant-renewal` bundle from the sibling FLUX repo,
through apply alone); `tests/golden/test_towers_public_golden.py` keys
its rows the same way. Regenerate the related-tables set with
`python tests/golden/related-star/_generate_golden.py` (the in-repo
`tests/fixtures/related-star` bundle, through apply alone);
`tests/golden/test_related_star_golden.py` keys its rows the same way. Regenerate the
kernel 0.2.0 related-tables set with `python tests/golden/related-star-v2/_generate_golden.py`
(the same bundle, planned with `fluxsim plan --kernel 0.2.0`);
`tests/golden/test_related_star_v2_golden.py` keys its rows the same way. Regenerate the shared-copies sets with `python tests/golden/shared-copies/_generate_golden.py`
(the in-repo `tests/fixtures/shared-copies` bundle, planned with `fluxsim plan --kernel 0.2.0` as it is written and with
`copies: true` added); `tests/golden/test_shared_copies_golden.py` keys a row for each set the same way. Regenerate the exact-counts sets with `python tests/golden/exact-counts/_generate_golden.py`
(the in-repo `tests/fixtures/exact-counts` bundle, which declares none of ADR 0016's keys, planned with `fluxsim plan --kernel 0.1.0` and
`--kernel 0.2.0` as it is written); `tests/golden/test_exact_counts_golden.py` keys a row for each set the same way. Regenerate the versioned sets with `python tests/golden/versioned/_generate_golden.py`
(the in-repo `tests/fixtures/versioned` bundle, a validity window with no history key, planned with `fluxsim plan --kernel 0.1.0` and
`--kernel 0.2.0` as it is written); `tests/golden/test_versioned_golden.py` keys a row for each set the same way. Regenerate the projected-rules set with `python tests/golden/projected-rules/_generate_golden.py`
(the in-repo `tests/fixtures/projected-rules` bundle, whose events and periodic emits declare derives that read the projected cells, planned with `fluxsim plan --kernel 0.2.0`
as it is written); `tests/golden/test_projected_rules_golden.py` keys a row for the set the same way. Every pinned `*.json` file must
stay under 200 KB; `test_golden_artifact_size.py` enforces it.
