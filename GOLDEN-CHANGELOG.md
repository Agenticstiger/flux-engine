# Golden changelog — `tests/golden/telco/`, `tests/golden/telco-public/` and `tests/golden/towers-public/`

Every deliberate move of a pinned artifact under `tests/golden/telco/`
(`plan.json`, `run-digest.json`, `seam-attestation.json`,
`fidelity-record.json`, `component-digests.json`) or
`tests/golden/telco-public/` (`run-digest.json`, `seam-attestation.json`,
`row-count.json`) gets one row here, keyed by that set's own
`run-digest.json`'s `runDigest` (the KERNEL-SPEC §11 digest taken over
that document with its self-referential fields masked — see
`tests/golden/test_telco_golden.py::_run_digest_value` and
`tests/golden/test_telco_public_golden.py::_run_digest_value`). A pinned
file that changed with no matching row here is a regression, not a
golden update: `test_a_golden_change_requires_a_changelog_row` in each
module enforces it, mirroring the same rule `fluxsim verify --update-golden`
already enforces for the runtime `<state_dir>/golden/GOLDEN-CHANGELOG.md`
(`flux_engine.core.trace.check_golden_update`).

Regenerate both sets with `python tests/golden/telco/_generate_golden.py`
(runs the full 25k-subject `tests/fixtures/telco-fidelity` bundle through
apply + ship, then the public `examples/telco-payment-recovery` bundle
from the sibling FLUX repo through apply alone), read the new
`runDigest`s back out of the regenerated `run-digest.json` files, and add
a row here per set in the same commit. Regenerate the towers set with
`python tests/golden/towers-public/_generate_golden.py` (the public
`examples/towers-tenant-renewal` bundle from the sibling FLUX repo,
through apply alone); `tests/golden/test_towers_public_golden.py` keys
its rows the same way. Every pinned `*.json` file must
stay under 200 KB — `test_golden_artifact_size.py` enforces it.
