usage: fluxsim validate [-h] [--profile PATH] [-j] bundle

Check a bundle against the FLUX schema and its cross-document rules. Reads
only; writes nothing.

examples:
  # check a bundle; nothing is written
  fluxsim validate ./bundle

  # also refuse what plan refuses about the profile the bundle pins (FLX-3105, 3109, 3110, 3113)
  fluxsim validate ./bundle --profile profile.json

arguments:
  bundle          path to the FLUX bundle directory

options:
  -h, --help      show this help message and exit
  --profile PATH  the profile document the Simulation pins (docs/spec/PROFILE-
                  SPEC.md): also refuse, as plan does, an overlay or a
                  parameter of the register that names a table or column it
                  does not describe, and a profile that is not the pinned one
                  (FLX-3105, 3109, 3110, 3113); a profile given to a
                  Simulation that pins none and the grade floor (FLX-4005) are
                  left to plan; without it no profile is read
  -j, --json      emit machine-readable JSON

docs: https://agenticstiger.github.io/flux/engine/reference/cli/validate.html
