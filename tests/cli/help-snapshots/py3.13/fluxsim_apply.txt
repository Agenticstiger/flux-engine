usage: fluxsim apply [-h] [--run-id RUN_ID] [--simulation-id SIMULATION_ID]
                     [--zone ZONE] [--jobs N] [--strict-coverage]
                     [--profile PATH] [--state-dir STATE_DIR] [-j]
                     bundle

Re-execute a recorded plan and write every run artifact: the population, the
events, the emit streams and their seam attestations, the run digest and the
receipt. Refuses when the plan or the bundle has moved since the plan was
recorded.

examples:
  # apply the plan recorded under that id (`plan` prints it)
  fluxsim apply ./bundle --run-id de72fa4b22711c52

arguments:
  bundle                path to the FLUX bundle directory

options:
  -h, --help            show this help message and exit
  --run-id RUN_ID       the run id to act on (as reported by `fluxsim
                        plan`/`fluxsim run`) (default: take a fresh plan
                        first)
  --simulation-id SIMULATION_ID
                        which Simulation document to resolve (default: the
                        bundle's only one)
  --zone ZONE           declared run zone, for sovereignty checks
  --jobs N              the most processes that may generate the rows of an
                        emit declared by statistics: a number (never more than
                        one per CPU) or auto for one per CPU; the run summary
                        says how many it used, and the rows and every digest
                        are the same whatever the number (default: FLUX_JOBS,
                        else 1)
  --strict-coverage     refuse the run when a column falls back to a type
                        default (an optional column nothing maps onto, a DATE
                        or TIMESTAMP column with no declaration of its own),
                        with a table of every such column, before any row is
                        drawn; a Simulation can ask for the same with
                        strictCoverage: true in its extensions; without either
                        the plan names those columns and goes on, and with
                        this flag the rows and every digest are the same
                        either way
  --profile PATH        the profile document the Simulation pins under
                        extensions['com.agentics.flux/1'].profile
                        (docs/spec/PROFILE-SPEC.md); refused when its digest
                        is not the pinned one, and when the Simulation pins
                        none; read only for a fresh plan, so refused with
                        --run-id
  --state-dir STATE_DIR
                        run-state directory (default: ./.flux)
  -j, --json            emit machine-readable JSON

docs: https://agenticstiger.github.io/flux/engine/reference/cli/apply.html
