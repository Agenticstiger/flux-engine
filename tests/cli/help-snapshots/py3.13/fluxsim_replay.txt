usage: fluxsim replay [-h] --run-id RUN_ID --assert-digest sha256:HEX
                      [--simulation-id SIMULATION_ID] [--zone ZONE]
                      [--allow-generator NAME] [--jobs N]
                      [--state-dir STATE_DIR] [-j]
                      bundle

Re-execute a recorded plan and refuse unless the run digest it produces is the
one asserted. The determinism claim, as a command.

examples:
  # re-execute the plan; refuse unless the run digest is the one asserted
  fluxsim replay ./bundle --run-id de72fa4b22711c52 \
      --assert-digest sha256:42d923fd6f4b8c0a1e7d59b2c8a4f36e0d15927acb3e8f6410d2b7c95e8a3f01

arguments:
  bundle                path to the FLUX bundle directory

options:
  -h, --help            show this help message and exit
  --run-id RUN_ID       the run id to act on (as reported by `fluxsim
                        plan`/`fluxsim run`)
  --assert-digest sha256:HEX
                        the runDigest this replay must reproduce, as
                        sha256:<64 hex chars>; the bare hex is accepted and
                        the prefix put back
  --simulation-id SIMULATION_ID
                        which Simulation document to resolve (default: the
                        bundle's only one)
  --zone ZONE           declared run zone, for sovereignty checks
  --allow-generator NAME
                        allow the generator plugin of that entry-point name to
                        be imported and run, while the replay generates the
                        rows again; repeat it for each plugin the bundle
                        declares under generators (without it the command is
                        refused, FLX-3119, before anything is imported); a
                        plugin is trusted code that runs with your rights, so
                        name only plugins you have reviewed; no environment
                        variable and no bundle key allows one
  --jobs N              the most processes that may generate the rows of an
                        emit declared by statistics: a number (never more than
                        one per CPU) or auto for one per CPU; the run summary
                        says how many it used, and the rows and every digest
                        are the same whatever the number (default: FLUX_JOBS,
                        else 1)
  --state-dir STATE_DIR
                        run-state directory (default: ./.flux)
  -j, --json            emit machine-readable JSON

docs: https://agenticstiger.github.io/flux/engine/reference/cli/replay.html
