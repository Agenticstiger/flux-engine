usage: fluxsim verify [-h] --run-id RUN_ID [--update-golden] [--reason REASON]
                      [--committed-slice EXPOSE_ID=file://PATH]
                      [--profile PATH] [--sample FRACTION] [--sample-block N]
                      [--sample-seed N] [--vectors VECTORS]
                      [--allow-declared-baseline-drift]
                      [--signing-key SIGNING_KEY] [--trust-key PATH]
                      [--state-dir STATE_DIR] [-j]
                      bundle

Re-check an applied run on five independent legs: the run's own artifacts
against its recorded digest, the golden regression, row conformance against
the referenced contract, the RFC-04 enforcement vectors, and every declared
fidelity check. One line per leg, with the flag that turns a `not checked` leg
into a result. A run whose plan pins a profile is also scored against it, per
property, table, dimension and overall, when the profile is passed with
--profile.

examples:
  # re-check an applied run on five independent legs
  fluxsim verify ./bundle --run-id de72fa4b22711c52

arguments:
  bundle                path to the FLUX bundle directory

options:
  -h, --help            show this help message and exit
  --run-id RUN_ID       the run id to act on (as reported by `fluxsim
                        plan`/`fluxsim run`)
  --update-golden       record this run as the golden baseline (requires
                        --reason)
  --reason REASON       why the golden baseline is being updated
  --committed-slice EXPOSE_ID=file://PATH
                        the committed real-data slice one expose's fidelity
                        check is measured against, as EXPOSE_ID=file://PATH;
                        repeatable, once per expose; the file holds one JSON
                        object per line, keyed by the expose's contract column
                        names (e.g. {"subscriber_id": "s-1", "amount":
                        "12.50"})
  --profile PATH        the profile document this run's plan pins
                        (docs/spec/PROFILE-SPEC.md): every declared fidelity
                        property with no --committed-slice is checked against
                        it, and the run is scored per property, table,
                        dimension and overall (docs/spec/SCORECARD-SPEC.md);
                        refused when its digest is not the pinned one, and
                        when the run pins none
  --sample FRACTION     compare each emit's means with the pinned profile on a
                        sample: FRACTION of its blocks of records, each mean
                        decided by its 95 per cent interval (docs/spec/SAMPLE-
                        SPEC.md)
  --sample-block N      records in a block of the sample (default: 1000);
                        needs --sample
  --sample-seed N       seed of the choice of blocks (default: 0); needs
                        --sample
  --vectors VECTORS     path to an RFC-04 vectors file
  --allow-declared-baseline-drift
                        exit 0 even when the bundle's declared
                        golden.baselineDigest does not match this run's
                        runDigest
  --signing-key SIGNING_KEY
                        file holding the 32-byte ed25519 seed a prior `fluxsim
                        ship` signed with; its public half becomes the trust
                        anchor, and the check says it is self-attested
  --trust-key PATH      file holding the 32-byte raw ed25519 PUBLIC key (raw
                        or hex -- the `publicKey` a fidelity record prints)
                        any fidelity record this run already holds is checked
                        against; without it, and without --signing-key, the
                        signature is reported as not checked
  --state-dir STATE_DIR
                        run-state directory (default: ./.flux)
  -j, --json            emit machine-readable JSON

docs: https://agenticstiger.github.io/flux/engine/reference/cli/verify.html
