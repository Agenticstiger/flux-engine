usage: fluxsim init [-h] [--contract FILE] [--profile FILE] [-j] directory

Write a small FLUX bundle and its FLUID contract into a directory, so a first
run needs nothing else checked out. With --contract and --profile, write a
bundle for your own data instead: the contract, and a Simulation declared from
the profile's published aggregates, with every number labelled in its
parameter register (from the profile, from the contract, or assumed, with the
reason). The directory must not exist yet, or must be empty: nothing is ever
overwritten.

examples:
  # write a project into a new directory
  fluxsim init demo

  # or into the current directory, if it is empty
  fluxsim init .

  # write a bundle for your own data, from its contract and its profile
  fluxsim init bundle --contract contract.orders.fluid.yaml \
      --profile orders.profile.json

arguments:
  directory        where to write the project (created if missing)

options:
  -h, --help       show this help message and exit
  --contract FILE  a FLUID contract: the bundle generates rows for each of its
                   exposes the profile describes; copied into the bundle
                   unchanged (needs --profile)
  --profile FILE   a profile document of that data (docs/spec/PROFILE-
                   SPEC.md), such as `fluid profile` writes: the Simulation
                   pins its digest and is declared from its published
                   aggregates; it stays outside the bundle (needs --contract)
  -j, --json       emit machine-readable JSON

docs: https://agenticstiger.github.io/flux/engine/reference/cli/init.html
